# Comprehensive Formula and Threshold Sensitivity Analysis

This report evaluates the impact of different scoring formulas and threshold configurations used in the system, without modifying the deployed dashboard.

---

## Objective

The purpose of this study is to:

* Maintain **low and stable scores during normal conditions**
* Ensure **clear separation between normal and abnormal behavior**
* Identify **which parameters significantly influence system behavior**

---

## Methodology

* Identical simulated timelines were used for all configurations
* Each configuration was tested across five scenarios:

  * Normal
  * CPU Stress
  * Memory Leak
  * Sudden Spikes
  * Critical Instability

Each candidate was evaluated based on:

* Stability in normal conditions
* Separation between normal and abnormal states
* Smoothness (low fluctuation)
* Ability to escalate toward critical conditions

---

## Important Observation (Key Insight)

During testing, it was observed that:

* Some parameters **strongly influence system behavior**
* Some parameters **have minimal or no visible impact**

This explains why multiple rows show identical values.

This is not an error — it indicates:

* The system is **stable and not overly sensitive**
* Certain parameters only affect **edge cases or rare conditions**

## Key Conclusions

* Higher rule-based weighting (alpha) improves separation between normal and abnormal behavior
* Not all parameters significantly affect output — some have **low sensitivity**
* Conservative thresholds reduce false positives
* Excessively sensitive configurations increase noise
* Temporal smoothing improves stability but excessive smoothing reduces responsiveness
